# 模型设置与基础文本对话

## 从哪里配置

临时运行桌面客户端后，点击左侧齿轮 → **模型设置**。也可以展开终端工具栏的机器人按钮，在 AI 面板中点击 **模型设置**。

1. 点击“新建配置”，填写配置名称和供应商提供的模型 ID。
2. 填写 API 基础地址和相对接口路径。例如基础地址 `https://model.example.com/v1/`，相对路径 `chat/completions`，最终请求地址为 `https://model.example.com/v1/chat/completions`。不要把密钥填进地址，也不要重复 `/v1`。
3. 需要认证时选择“设置 / 替换密钥”，填写 API Key。无认证的本地模型服务可以取消“此服务需要 API Key”，并选择“清除密钥”。
4. 上下文窗口、最大输出按供应商说明填写。8192 / 1024 是初始值，程序不会自动探测模型窗口。输出与安全预留之和必须小于窗口。
5. 点击底部“保存配置”，返回终端，展开 AI 面板并选择该配置，发送一条文本消息。

模型页沿用主分支的设置控件与主题，内容区最大 1280px，大屏右侧保留留白。左侧“我的模型”用于切换配置；编辑区足够宽时，模型渠道/身份认证与接口/生成参数分成两栏。地址占整行，名称/模型 ID、接口路径/输出参数、窗口/最大输出、超时/响应上限成对排列。高级参数默认收起，保存栏固定在编辑区底部。窄窗口中配置列表变为横向排列，表单和列表各自滚动。AI 面板模型下拉框旁的设置图标可直接进入此页面。

配置名称可以直接修改并保存。名称仅用于显示，内部配置 ID 保持不变，因此改名不改变 API Key 的加密绑定，也不改变已有会话归属。旧配置首次升级后以原来的 ID 作为显示名称；新配置使用独立内部 ID。页面已去掉额外的“模型设置”和“编辑配置”标题区，直接展示字段。

“接口协议”可选 Chat Completions 或 Responses，切换时相对路径切换为对应默认值；自定义代理路径可继续编辑。Responses 的输出参数固定为 max_output_tokens。

“已配置”表示字段和密钥满足配置要求；首次发送才验证网络、认证和模型协议。模型不支持 `max_completion_tokens` 时，可在“接口与生成”中切换到 `max_tokens`，超时和响应上限也在这里修改。高级参数提供安全预留、自动整理触发比例、Temperature 和推理强度；后两者默认不发送，仅在供应商明确支持时设置。推理强度快捷选项与下拉框同步，蓝色边框和勾选表示当前选择。

配置保存后立即用于后续请求，不需要重启或修改 `.env`。回复期间不能修改模型或切换配置；切换配置会进入新的空会话，原来的会话可以从对应模型的历史中打开。

## 密钥与本地数据

API Key 使用 Windows DPAPI 加密，保存在当前工作区 SQLite 模型配置表中；与 Windows 用户、应用用户和配置 ID 绑定。读取配置只返回“是否已保存”，不返回密钥。设置页面中的新密钥输入仅在本次编辑期间存在，保存成功、切换配置或关闭设置后清除。

编辑时默认“保留现有密钥”。更换 API 基础地址时必须明确替换或清除密钥，防止将旧密钥发给新的服务。不要将加密数据库视为可以跨 Windows 用户直接恢复的明文配置。

多窗口同时编辑会检查配置版本。提示版本冲突时点击“重新加载配置”，再重新编辑。删除配置需要在页面中确认；历史仍保留在数据库中。重新建立同名配置会使用新内部 ID，不会自动重新关联已删除配置的历史。旧版 Java 聊天记录自动导入属于 E4，本阶段不做导入。

## 对话、停止与恢复

- 当前支持文字提问、纯文本粘贴、流式回复、停止生成和历史会话。已接入长对话自动整理；聊天附件、工具执行和审批尚未接入，面板会说明这些边界。
- 回复期间切换终端页签不会改变该会话的目标。继续旧会话会使用原来的目标；原 SSH 终端关闭或重连后，需要连接目标服务器并新建会话。普通未绑定会话保持未绑定，选择新的终端不会偷偷重新绑定。
- “历史”按模型读取 Rust 数据库，支持加载更多会话。完整回复显示持久结果；取消、失败和中断显示部分文本与实际状态，不会当成成功回复。
- 重读历史不会调用模型。历史中仍在生成的请求会短间隔刷新，也可手动刷新或停止该请求。硬退出遗留的请求在后端租约到期后标记为中断，不会自动重新生成。
- 点击旧用户消息的“恢复请求”可以放回输入框；手动重新发送会创建新的 requestId，属于新的模型请求。
- 接近设置的输入容量比例时，会尝试整理较早的完整对话，再继续当前请求。原始历史仍保留。若必需输入自身超限、摘要无效或无法降到较低水位，会提示缩短输入/新建会话或检查模型；不会把整理失败显示为成功。

## 在桌面验证自动整理

1. 在客户端目录重新启动 npm run tauri dev，让 Rust 库重新编译。只刷新浏览器前端无法更新 Rust；已有安装包尚未包含 C2。
2. 打开“设置 → 模型设置 → 高级参数”，将“自动整理触发比例”暂设为 60%，保存。该百分比基于窗口扣除最大输出和安全预留后的可用输入。默认是 75%，范围 1–99%；低水位为触发水位的 80%。测试完成可改回 75%。
3. 使用支持流式文字和普通非流式 Chat Completions 的现有模型；非流式调用还需能按提示返回严格 JSON 摘要。若模型实际窗口至少 8192，可用保守的 8192 窗口、1024 输出、512 安全预留较快触发测试；配置窗口不要超过供应商真实能力。
4. 新建文字会话，先发送短的任务/约束，再分多轮发送较长文本并追问前文。第一条任务目标会被保留，因此不要用超长首条输入来测试压缩；单条用户输入最多 16000 UTF-8 字节。
5. 检查后续回复能继续、早先约束仍被记住，打开“历史”仍能看到全部原始消息。在长对话等待回复时点击停止，再显式发送新消息，应可继续；不会自动重发停止的请求。

当前整理会在回复首段文字前增加一次摘要等待，失败或缩减不足最多再尝试一次；网络错误不自动重试。只有完整原上下文本身仍能发送时才允许原文回退，否则明确报错。C5 尚未提供上下文占用/整理状态标记，等待时间不能作为成功证据；模型自由摘要的语义质量仍需要用户实际验证。

## 使用 Responses 远端整理

1. 重新编译并重启桌面开发程序。在“模型设置 → 模型渠道 → 接口协议”选择 Responses，确认模型 ID、基础地址和相对路径；通常相对路径为 responses。
2. 供应商须支持 responses、responses/input_tokens，以及要启用整理时的 responses/compact。仅有 Chat Completions 的服务不能通过换路径变成 Responses；保留原协议配置即可继续使用 C2 普通模型摘要。
3. 展开高级参数，明确开启“供应商远端整理”，再设置触发比例。该开关默认关闭；关闭时 Responses 只按硬容量对话，不执行远端整理。输入占用由供应商计数，超限不会静默截断。
4. 新建会话，用短任务开始，再进行长对话，检查继续回复、原始历史、整理等待期间停止及手动续聊。供应商返回的完整窗口保存在 Rust，前端不展示密文。
5. 更换协议、接口路径、模型 ID 或密钥后，新建会话。原会话的供应商窗口不能跨配置复用；仅修改显示名称、窗口预算或触发比例可继续使用。

一次整理最多发一个 compact 请求，另外会做输入计数来检查当前输入、来源与新窗口容量；因此回复首段前可能增加等待。失败或缩减不足时，只有完整原窗口仍可发送才回退，原历史和旧检查点保持。C5 的整理状态/占用提示尚未实现，不能把等待时间当成成功证据。

## 项目与聊天历史

用户已撤销最近两次窗口 UI 改造。当前恢复原来的左侧服务器列表、中央终端和右侧 Agent 面板；设置从原导航进入，保留原有模型/外观分类。没有 Codex 项目侧栏、最左图标栏或主区对话/终端切换。

持久项目/作用域和历史恢复逻辑仍保留。打开右侧 Agent 的“历史”，可查看项目分组和普通聊天、创建项目、选择项目记录。点击原记录使用同一 sessionId/原模型，并复用或连接对应服务器；断线仍能看历史和讨论已有内容。新建项目聊天才产生新的独立上下文，原始日志/检查点/Responses 窗口不合并、不删除。

在“历史”中新建项目时，仍从已保存服务器选择。服务器管理使用原来的左侧连接列表。终端在中央，Agent 在右侧，可用原有 AI 展开/收起按钮。当前服务器任务的标题/状态仍按当前项目/历史绑定显示，切换终端页签不改变聊天归属；来源终端选区只能加入对应已验证项目。

可检查：打开项目 A 的原记录，关软件重开，再从 Agent“历史”选择同一条记录；原文应保持，连接后可继续提问。打开 B 的记录不带入 A 历史。真正 Agent 工具执行/审批仍属于 D，自动整理的可见占用/状态仍属于 C5。本次仅撤销窗口 UI，不回退 schema 10 或历史数据。

# 模型设置与基础文本对话

主导航仅保留终端、本地工作区、模型设置、工具与 Skills、外观。展开宽度调整为 208px，标题与说明允许换行，窗口较矮时导航内部滚动。收起后悬停图标显示深色浮层，包含名称与用途；键盘聚焦同样显示，移出、失焦、点击、滚动、调整窗口或 Esc 关闭。浮层通过 Portal 显示，避免被导航容器裁切。

终端使用窗口命令行图标，工作区使用数据窗口，模型使用芯片，工具使用扩展拼图，外观使用调色盘；折叠按钮按状态显示展开 / 收起方向。主导航与独立设置页共用同一菜单配置，删除“关于试用版”入口、页面和闲置 CSS。旧更新页面请求回到现有本地工作区页面。本次按用户此前要求未运行测试、类型检查、构建或实际界面验收。

操作反馈统一使用顶部浮动提示：模型、工具额度、MCP、Skills 和本地工作区的保存结果不再常驻页面。MCP / Skills 弹窗独立保存后立即提示；模型删除使用确认弹窗，完成后给出浮动提示。详见 [操作结果提示](operation-feedback.md)。

## 项目历史与审批状态

服务器工具对话同样使用模型真实流式正文，执行工具后的回答会随返回增量显示。模型服务若忽略流式请求并仅返回完整 JSON，则收到完整回复后显示；程序不会通过重复请求或再次执行 SSH 模拟流式效果。

历史记录使用独立悬停预览浮层：停留片刻后显示多行标题、所属项目与创建时间。浮层优先出现在侧栏右侧，空间不足时翻转或调整位置；移入浮层可继续查看，滚动、按 Esc、点击外部或窗口失焦时关闭。键盘聚焦历史行也能显示预览；不再叠加浏览器自带的标题提示。

审批卡片的“命令用途”优先显示工具提供的 explanation。旧记录若只有“未提供说明”占位文字，df -h、whoami、pwd 等完整简单命令会显示对应默认用途；复合脚本不会按单个命令前缀解释。

对话需要人工审批工具操作时，左侧对应历史标题旁显示绿色“等待审批”标签与旋转状态图标；批准、拒绝、取消或过期后清除。自动审查尚未要求人工确认时不显示标签。

普通生成或执行中的对话在标题右侧显示灰色旋转圆圈，完成或停止后移除；等待审批时由绿色审批标签替代，避免重复显示圆圈。选中的历史记录保持浅灰圆角底色，生成期间也不降低整行透明度。减少动态效果偏好下圆圈保持静态。

项目标题右侧保留“⋯”选项和新对话编辑图标。“移除项目”只移除分组，聊天、命令、工具输出和原有服务器绑定全部保留，记录显示在“未分组对话”中；当前对话不会被清空。项目移除状态会持久保存，重启不会自动恢复分组。对话行的“删除对话”仍会在确认后删除该条聊天及工具记录，进行中的对话不能删除。

## 从哪里配置

模型设置页只展示已保存的配置卡片，包含配置名称、模型 ID、供应商、协议、地址和配置状态。没有配置时展示空状态；加载失败显示重试入口。点击“新建配置”或卡片“编辑”打开配置弹窗，删除先确认。保存成功关闭弹窗并更新列表，取消丢弃草稿，失败保留输入。

弹窗先选择供应商，下拉显示品牌图标与“OpenAI 兼容 / Anthropic 兼容 / Google 兼容 / DeepSeek”，不附带说明列。OpenAI 可选 Chat Completions、Responses；Anthropic 使用 Messages；Google 使用 GenerateContent；DeepSeek 可选 Chat Completions（默认）、Messages。API 基础地址仅以占位文字提示对应官网地址，新建和切换供应商/协议时不自动填写；用户输入或已有配置的地址保持原值；留空保存或查询上游模型时，使用输入框提示中的默认官方地址。DeepSeek 使用可选 supplier 字段保存身份，底层复用原协议；没有该字段的旧配置继续从协议恢复品牌，不猜测 URL 或模型名称，无需数据库 schema 迁移。

API 基础地址使用应用内建议列表，替代浏览器/WebView 原生“保存的信息”下拉框，并关闭该字段及配置表单的原生自动补全。列表区分“官方默认”（标注“留空时使用”）和“已保存地址”；已保存地址只取自现有模型配置，不读取浏览器输入历史、不另存未保存草稿。地址去重，最多展示 8 个已保存地址；输入时筛选，长地址省略并可悬停查看完整值。点击地址即可选用，选择官方默认恢复空输入、由保存/查询统一解析；支持方向键、回车确认、Esc 收起，手动输入不自动替换。浮层沿用浅色/深色主题，空间不足向上展开。

“请求参数”在弹窗内直接展示，安全预留、自动整理比例与 Temperature 宽屏并排、窄屏单列。数字控件保留常用档位和手动输入；整理比例仍为 1–99，Temperature 上限按协议限制，留空不发送。Responses 的远端整理开关仅在选择 Responses 时出现。

推理强度移至聊天输入框底部的模型选择旁，提供默认不发送、关闭 none、极低 minimal、低 low、中 medium、高 high、很高 xhigh。选择自动保存到当前模型，下一条消息生效，不清空当前会话。仅选择供应商支持的档位；默认与 none 有不同含义。保存时读取最新配置并合并推理选项，保留密钥与其他参数并继续校验版本；失败保留原档位并给出浮动提示。保存期间阻止发送、队列消费、模型切换及设置页修改。读取失败可在同一入口重试，切换模型或设置页保存后重新读取。

本次参数布局与推理入口调整按用户此前要求未运行测试、类型检查、构建或实际界面验收；已同步既有测试适配，未修改后端请求协议。

临时运行桌面客户端后，点击左侧主导航中的 **模型设置**，与“终端”入口同级。也可以展开终端工具栏的机器人按钮，在 AI 面板中点击 **模型设置**。

1. 点击“新建配置”打开弹窗，先选供应商；OpenAI 再选择接口协议。填写配置名称和供应商提供的模型 ID。
2. 填写 API 基础地址和相对接口路径。例如基础地址 `https://model.example.com/v1/`，相对路径 `chat/completions`，最终请求地址为 `https://model.example.com/v1/chat/completions`。不要把密钥填进地址，也不要重复 `/v1`。
3. 需要认证时，在 API Key 输入框填写密钥，并打开输入框右侧的“使用 API Key”。已配置时输入框提示“已配置，留空表示不修改”，不会回显已保存的密钥；未配置时提示“未配置”。输入新值则设置/替换，留空保留原状态。无认证的服务关闭开关即可，已存密钥保留，请求不携带密钥。
4. 上下文窗口、最大输出按供应商说明填写。8192 / 1024 是初始值，程序不会自动探测模型窗口。输出与安全预留之和必须小于窗口。请求超时、最大响应同样支持常用档位与手动输入；响应档位用 KiB/MiB 显示，保存的仍是精确字节数。安全预留、自动整理比例和 Temperature 在“请求参数”中直接展示，提供常用档位及手动输入，窄窗口自动换行。
5. 点击底部“保存配置”，返回终端，展开 AI 面板并选择该配置，发送一条文本消息。

模型页沿用现有设置控件、浅色/深色主题与圆角卡片，内容区最大 1280px；配置卡片随可用宽度排列。配置弹窗宽屏两栏、窄屏单栏，正文内部滚动、保存栏固定底部，支持 Esc / 点击遮罩关闭和焦点管理；保存期间禁止关闭，嵌套删除确认时暂停编辑弹窗。AI 面板模型下拉框旁的设置图标可直接进入此页面。

配置名称可以直接修改并保存。名称仅用于显示，内部配置 ID 保持不变，因此改名不改变 API Key 的加密绑定，也不改变已有会话归属。旧配置首次升级后以原来的 ID 作为显示名称；新配置使用独立内部 ID。页面展示卡片，编辑字段集中在弹窗内。

OpenAI 下可选择 Chat Completions 或 Responses，Anthropic 使用 Messages。协议切换时采用对应默认路径，自定义代理路径可继续编辑；Responses 输出参数固定 max_output_tokens，Messages 固定 max_tokens。

“已配置”表示字段和密钥满足配置要求；首次发送才验证网络、认证和模型协议。模型不支持 `max_completion_tokens` 时，可在“接口与生成”中切换到 `max_tokens`，超时和响应上限也在这里修改。高级参数提供安全预留、自动整理触发比例、Temperature 和推理强度；后两者默认不发送，仅在供应商明确支持时设置。推理强度快捷选项与下拉框同步，蓝色边框和勾选表示当前选择。

配置保存后立即用于后续请求，不需要重启或修改 `.env`。回复期间不能修改模型或切换配置；切换配置会进入新的空会话，原来的会话可以从对应模型的历史中打开。

## 密钥与本地数据

API Key 使用 Windows DPAPI 加密，保存在当前工作区 SQLite 模型配置表中；与 Windows 用户、应用用户和配置 ID 绑定。读取配置只返回“是否已保存”，不返回密钥。设置页面中的新密钥输入仅在本次编辑期间存在，保存成功、切换配置或关闭设置后清除。

编辑时留空保留现有密钥；输入新值后保存替换。关闭“使用 API Key”仅停用认证，不删除密钥。更换 API 基础地址可直接保存，密钥留空继续保留已存密钥；输入新密钥时才替换。无需密钥的服务可直接关闭开关。不要将加密数据库视为可以跨 Windows 用户直接恢复的明文配置。

多窗口同时编辑会检查配置版本。提示版本冲突时点击“重新加载配置”，再重新编辑。删除配置需要在页面中确认；历史仍保留在数据库中。重新建立同名配置会使用新内部 ID，不会自动重新关联已删除配置的历史。旧版 Java 聊天记录自动导入属于 E4，本阶段不做导入。

## 对话、停止与恢复

- 当前支持文字提问、纯文本粘贴、流式回复、停止生成和历史会话。已接入长对话自动整理；聊天附件、工具执行和审批尚未接入，面板会说明这些边界。
- 回复期间切换终端页签不会改变该会话的目标。继续旧会话会使用原来的目标；原 SSH 终端关闭或重连后，需要连接目标服务器并新建会话。普通未绑定会话保持未绑定，选择新的终端不会偷偷重新绑定。
- “历史”按模型读取 Rust 数据库，支持加载更多会话。完整回复显示持久结果；取消、失败和中断显示部分文本与实际状态，不会当成成功回复。
- 重读历史不会调用模型。历史中仍在生成的请求会短间隔刷新，也可手动刷新或停止该请求。硬退出遗留的请求在后端租约到期后标记为中断，不会自动重新生成。
- 点击旧用户消息的“恢复请求”可以放回输入框；手动重新发送会创建新的 requestId，属于新的模型请求。
- 接近设置的输入容量比例时，会尝试整理较早的完整对话，再继续当前请求。原始历史仍保留。若必需输入自身超限、摘要无效或无法降到较低水位，会提示缩短输入/新建会话或检查模型；不会把整理失败显示为成功。

## 在桌面验证自动整理

1. 在客户端开发工作区重新运行 `npm run tauri dev`，让 Rust 库重新编译。只刷新前端无法更新本轮原生实现；已有安装包不能代表最新源码。
2. 打开“设置 → 模型设置 → 请求参数”，将“自动整理触发比例”暂设为 60%，保存。该百分比基于窗口扣除最大输出和安全预留后的可用输入。默认是 75%，范围 1–99%；低水位为触发水位的 80%。测试完成可改回 75%。
3. 使用支持流式文字和普通非流式 Chat Completions 的现有模型；非流式调用还需能按提示返回严格 JSON 摘要。若模型实际窗口至少 8192，可用保守的 8192 窗口、1024 输出、512 安全预留较快触发测试；配置窗口不要超过供应商真实能力。
4. 新建文字会话，先发送短的任务/约束，再分多轮发送较长文本并追问前文。第一条任务目标会被保留，因此不要用超长首条输入来测试压缩；单条用户输入最多 16000 UTF-8 字节。
5. 模型选择区下方会显示“最近输入”。首次发送前为“未测量”；发送后显示占用比例与“估算”来源，点击可展开 token 数、可用容量、模型窗口、输出/安全预留、触发比例及记录时间。分母是扣除预留后的可用输入，不是完整模型窗口。
6. 达到触发条件并实际开始摘要时显示“正在整理上下文”；检查点真正保存后显示“本次整理已保存”，已整理次数增加，后续测量反映整理后的输入。失败时显示失败/回退并保留历史与旧次数，不能仅凭等待时间判断成功。
7. 检查后续回复能继续、早先约束仍被记住，左侧原记录仍能看到全部消息。整理等待时停止，再显式发送新消息，应可继续；停止的请求不会自动重发。若有效检查点先于停止提交，保留这次真实成功及次数；未提交的取消不会增加次数。
8. 切换普通/项目聊天、重开历史或重启软件，状态按原聊天恢复，不混入另一会话。历史中从未测量过的会话保持“未测量”，仍可显示已有检查点次数。强制退出时的整理中状态在租约过期后显示中断，不自动继续摘要。

当前整理会在回复首段文字前增加一次摘要等待，失败或缩减不足最多再尝试一次；网络错误不自动重试。只有完整原上下文本身仍能发送时才允许原文回退，否则明确报错。模型自由摘要的语义质量仍需要实际验证。

“最近输入”是最近一次请求准备阶段测得的完整输入快照，不包含未发送草稿、回复后的新内容或累计 token 消耗。Chat Completions 使用启发式估算，Responses 使用供应商计数，不把密文字节数当 token。配置修改后以新请求测量为准；读取历史/状态不额外请求模型。状态读取失败可点击“重试”，不会自动重新发送对话。没有手动整理按钮或命令执行入口。

### 复验多次整理后的事实保留

实测曾出现“公开编号在第三、第四次摘要中存在，第五次摘要丢失”的问题。修复后普通摘要会提取带原始用户事件出处的 `retainedUserFacts`；程序在后续整理中保留已收录事实，并发送到后续模型请求，不只依赖模型重复概括。旧历史兼容，schema 仍为 11。

1. 重新运行 `npm run tauri dev`，等待 Rust 重编译；无需清空数据。
2. 在原聊天重新发送：`恢复演练的报告编号是 QSB-7042。这是公开业务编号，不是密码或认证信息，请在后续交接中保留。` 已丢失的旧摘要不会因升级自动回填。
3. 连续多轮讨论部署检查、版本更新、备份恢复等其他话题，每轮让模型给出约 500～700 字的分析，不再提示编号。
4. 经过至少两次整理后询问：`我们约定的恢复演练报告编号是什么？只回答编号，没有依据就回答不确定，不要猜测。`
5. 次数增加不能单独证明编号已被摘要覆盖，因为最近完整轮次可能仍保留原文；必要时结合检查点出处核对。还可重启后打开原聊天再问一次。

这些事实最多 32 条，每条最多 512 UTF-8 字节，仍计入输入容量；达到限制时不会偷偷删除旧事实。初次提取与模型回答仍需实际验证，不等于所有聊天细节都被永久记住。请用公开业务信息测试，不使用真实密码或 API Key。

## 对话输入区

输入区固定在聊天面板底部，与消息列对齐同宽，使用圆角和阴影区分层次，聊天记录独立滚动。模型选择和模型设置入口位于输入卡片右下工具栏；左下“+”沿用附件入口，Rust 文字阶段仍禁用附件并保留原因提示。右侧蓝色圆形上箭头发送消息，生成期间变为停止按钮。Enter 发送、Shift+Enter 换行以及原有草稿、粘贴和停止行为保持。

压缩中提示在模型回复区域显示处理时长与扫光高亮文字。上下文占用改为输入框模型设置按钮右侧的进度圆环，鼠标悬浮或键盘聚焦可查看百分比、真实整理次数、状态与预算；未知占用显示虚线环，状态读取失败时可点击圆环重试。顶部不再显示整条状态栏。模型回复不再显示机器人头像，普通等待只显示轻量动画。

## C6：缩小窗口、停止续聊与重启恢复

本轮修改在 Rust 库内；重新运行 `npm run tauri dev` 等待编译即可使用，没有新的前端按钮，数据库仍为 schema 11。先记下原配置，测试结束后恢复。

1. 确认接入服务至少支持 16384 Tokens。上下文窗口先设为 `16384`、最大输出 `2048`，请求参数中安全预留 `512`、触发比例 `60%`。
2. 新建聊天并发送：`我们只讨论方案，不执行命令。恢复演练报告编号是 REC-5826，每日 03:15 备份，保留 9 天；请在后续交接中保留这些公开业务事实。不要重启服务或覆盖当前数据库。` 再多轮讨论其他话题，直到发生一次真实整理。
3. 保存上下文窗口 `8192`，回到同一条历史继续提问。展开状态详情应看到最近一次请求采用新窗口；安全整理成功才增加次数。若旧上下文/新输入无法压到容量，允许明确报错，原始历史仍应保留，不能无休止整理或静默裁剪。
4. 整理等待期间点停止，再发：`新增约束：备份文件也不允许删除。请复述目前约束和恢复演练的三个业务事实，只讨论，不执行。` 应沿用原会话；停止前已提交的整理仍计数，未提交不加次数。
5. 退出开发程序、重新启动后从历史打开同一聊天，核对原文和已提交次数，再询问报告编号、时间、保留天数。生成中异常中断与正常用户停止是两种状态，分别显示中断/取消；不需要为了测试强杀电脑或改用户数据库。

前端生成期间仍锁定发送。整理期间直接追加用户消息的竞态由内核测试覆盖，本次修复确保这类有效补充不会在后续模型请求中漏掉，不表示新增了消息插队功能。附件对话仍未接入：附件引用会明确拒绝，不读取媒体或假装成功；真实图片/PDF 和媒体预算在 E1 实现。

验证使用临时 SQLite 和本机回环模型：自动整理 25 项、上下文状态 4 项及严格 Clippy 通过。本轮未修改前端业务，不重复前端、Tauri、构建或完整 GUI 测试；真实模型的摘要选择与回答质量由用户复验。

## 使用 Responses 远端整理

1. 重新编译并重启桌面开发程序。在“模型设置 → 模型渠道 → 接口协议”选择 Responses，确认模型 ID、基础地址和相对路径；通常相对路径为 responses。
2. 供应商须支持 responses、responses/input_tokens，以及要启用整理时的 responses/compact。仅有 Chat Completions 的服务不能通过换路径变成 Responses；保留原协议配置即可继续使用 C2 普通模型摘要。
3. 在请求参数中明确开启“供应商远端整理”，再设置触发比例。该开关默认关闭；关闭时 Responses 只按硬容量对话，不执行远端整理。输入占用由供应商计数，超限不会静默截断。
4. 新建会话，用短任务开始，再进行长对话，检查继续回复、原始历史、整理等待期间停止及手动续聊。供应商返回的完整窗口保存在 Rust，前端不展示密文。
5. 更换协议、接口路径、模型 ID 或密钥后，新建会话。原会话的供应商窗口不能跨配置复用；仅修改显示名称、窗口预算或触发比例可继续使用。

一次整理最多发一个 compact 请求，另外会做输入计数来检查当前输入、来源与新窗口容量；因此回复首段前可能增加等待。状态条标注“供应商计数”，不展示完整窗口中的密文。失败或缩减不足时，只有完整原窗口仍可发送才回退，原历史和旧检查点保持，失败不会显示为成功。

## 工具默认启用与审批

函数工具能力默认启用，不再提供单独开关，旧模型配置读取时自动适配。在已连接的服务器对话中，SSH 工具自动可用；发送前核验并绑定该对话原服务器，不随当前终端页签切换目标。断线时仍可讨论历史，重连后继续使用工具。

输入框中的“请求批准 / 帮我批准 / 完全访问权限”表示当前任务的工具审批方式。安全的任务输出回读无需逐次批准；需要授权的操作由各工具的原生适配器按同一任务策略处理。Skill 本身不授予权限，其实际工具调用仍经过授权入口。

生成中及等待审批时均可切换审核边界，保存后的策略用于尚未执行的请求；已经准入的命令继续运行。切换到“帮我批准”会重新审查待确认请求，切换到“完全访问权限”会放行当前任务尚未执行的有效请求，收紧权限会撤回未使用的自动批准与短期授权。命令卡片在命令后展示无输出超时；展开说明可查看模型随命令提供的简要用途。旧记录没有用途说明时，只解释可确定的简单命令，其他情况明确提示未附说明。

目前已接入 SSH、MCP、Skills 按需读取及单层子任务；普通对话不注册 SSH。新增工具必须实现原生授权适配，单独注册函数不会获得执行权限。工具轮次支持 Chat Completions、Claude Messages 与 Responses；按协议保留并回传推理字段、思考签名或原生 reasoning 项。默认启用不保证供应商实现 function calling，协议错误仍会明确返回。

## MCP JSON 配置

设置 → 工具与 Skills → MCP 服务，页面只显示服务数量、启用数和简短名称摘要。点击“配置 MCP”打开设置弹窗，在带 JSON 语法高亮及行号的编辑器中管理全部服务。支持格式化、插入停用示例和就地错误提示。多个服务放在同一个 `mcpServers` 对象中，最多 8 个。服务名为 1–24 个英文字母、数字、下划线或连字符；省略 enabled 表示启用，`enabled: false` 或 `disabled: true` 可停用。

重新打开弹窗时，每个服务都明确显示 `enabled: true` 或 `enabled: false`，不再省略启用状态。本次 enabled 显示与保存范围修复按用户要求仅修改代码，未运行测试、类型检查或构建；包含原生 Rust 修改，需要重新编译客户端后加载。

```json
{
  "mcpServers": {
    "aisearch-mcp-server": {
      "type": "streamableHttp",
      "description": "搜索实时信息，支持总结回复。",
      "baseUrl": "https://qianfan.baidubce.com/v2/ai_search/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_API_KEY"
      }
    },
    "AISearch": {
      "url": "http://appbuilder.baidu.com/v2/ai_search/mcp/sse?api_key=YOUR_API_KEY"
    },
    "local-tools": {
      "command": "node",
      "args": ["C:/mcp/server.js"],
      "env": {
        "API_KEY": "YOUR_API_KEY"
      },
      "enabled": false
    }
  }
}
```

HTTP 支持 `url` / `baseUrl` 和 `headers`，旧的 `transport` 字段也可读取；type 可为 `streamableHttp`（别名 http / streamable-http）、sse 或 stdio。省略 type 时，带 command 的项推断为 stdio，路径以 /sse 结尾的地址推断为旧版 SSE，其他 URL 推断为 Streamable HTTP。两个同名别名字段同时存在时须保持一致。description 保存并提供给模型发现服务使用。

stdio 的 command 为程序名称或绝对路径，args 为参数数组，env 为字符串值对象；Windows 的 npx / npm 使用对应 .cmd 启动器。旧版 env 名称数组可读取；`inheritEnv` 可列出额外继承的本机环境变量名，与 env 对象同时使用时保留两类配置。

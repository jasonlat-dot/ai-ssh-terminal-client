# SFTP 文件管理客户端

服务器列表中每台主机下方的“文件管理”，以及终端工具栏的文件夹按钮，都会打开独立文件管理窗口。无需建立终端连接。连接前可设置远程根目录：留空使用账号默认目录，填 `/` 可浏览账号有权限访问的整个文件系统；根目录在该会话内固定。

左右两栏分别显示真实本地目录和远程目录，按需读取，不预先递归加载。可以输入目录路径、返回上一级、刷新、新建目录；单击选择文件或目录，双击或 Enter 进入目录。中间箭头上传或下载选中项，目标为另一栏当前目录。目录传输包含嵌套文件、零字节文件与空目录。

- 上传同名文件可选择报错或跳过，不覆盖已有文件。
- 下载提前检查相对路径、符号链接、已有目标，以及 Windows 保留名称和大小写冲突。不支持特殊文件或跟随符号链接。
- 收起窗口、Esc 或右上角关闭弹窗按钮只隐藏界面，任务继续；底部“文件 · 主机名”可恢复。明确点击“关闭会话并取消传输”才关闭独立 SFTP 会话。终端关闭不影响文件管理。
- 显示扫描、等待、传输、待本地确认、完成、失败和取消状态。100% 字节进度不代表完成；零字节任务显示条目进度。
- 可以取消任务、查询最新状态，并对失败或待确认任务“重查并重试”。取消后需创建新任务。
- 会话到期或服务端重启后不会自动创建会话，由用户重新打开。

## 实现

`src/api/sftp.ts` 是 Tauri IPC 适配；`src/state/useSftp.ts` 管理独立窗口状态；`src/components/Sidebar.tsx` 实现双栏及任务列表。

`src-tauri/src/sftp/` 负责本地文件、HTTP 与 SSE。文件正文通过 Rust 直接读写和 HTTP 流传输，不进入 JavaScript 内存、不经过聊天附件或 MinIO。每窗口最多两个文件并发；429 使用有上限的退避。HTTP 内容流不使用固定总时长限制，读超时按连续无进展计算。

JSON、SSE 与文件流使用同一个 Rust HTTP Client 和 Cookie 容器。目前项目没有登录流程，沿用服务端配置的匿名身份，不提交客户端自报 userId。服务端 `anonymous-user-id` 需要与保存的连接所属用户一致。将来接入登录时，须把认证接入该原生 Client；WebView Cookie 不会自动共享到 Rust。

下载先写同目录 `.sftp-*.part`，检查清单字节数、服务端 SENT 状态，flush/sync 并关闭本地文件，再使用不覆盖目标的原子 hard-link 提交，最后 confirm。确认请求丢失时保留已保存条目记录，只重试确认。目标文件系统必须支持硬链接；不支持时显示保存错误，不回退到可能覆盖目标的写入方式。临时文件在错误与取消时清理。

SSE 按完整行解码 UTF-8，支持 CRLF、心跳及分块边界；断线退避重连，重查任务快照；收到 `session-closed` 或 401/403/404 停止重连。窗口、任务及本地重试记录只在当前进程内有效。

纯浏览器预览会提示使用桌面客户端，不提供演示文件替代真实目录。

## 验证

- `npm run build`
- `npm run test:sftp`：远程路径、零字节进度、旧快照保护。
- `npm run test:files`：现有聊天文件上传回归。
- `cd src-tauri && cargo test sftp::`：路径与 SSE 单元测试，以及临时本机 HTTP 服务上的原生传输测试（空文件、空目录、截断响应、确认重试、同名保护、429 退避）。运行完整 Tauri crate 需要对应平台开发库。

实际 SSH 联调仍需可用的后端和已保存 SSH 配置。建议用临时目录验证上传/下载、关闭终端后继续传输、传输中取消、权限不足、断网重试、会话回收和不同根目录。

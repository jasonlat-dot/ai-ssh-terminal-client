# 独立文件上传

入口：应用顶部「文件上传」，或终端文件面板的「独立上传」。不要求建立 SSH 会话。
选择后自动加入队列，每个请求只有一个文件，最多并发两个。关闭弹窗或切换终端不影响上传。
当前记录保存在应用内存中，刷新、退出客户端或切换后端会清空；失败记录保留 File 对象供手动重试。

## 实现位置

- `src/api/client.ts`：从原 SSH 封装提取的公共 JSON 响应客户端，保留 fetch 与原有认证行为，处理 `/api/v1` 去重和后端 `info`。未引入新的直连存储、代理或认证路径。
- `src/api/files.ts`：`POST /api/v1/files`、完整返回类型、响应校验和签名地址有效期处理。
- `src/config/fileUpload.ts`：20 MiB、扩展名白名单、并发数和超时集中配置。
- `src/state/fileUploads.ts`：独立队列、同文件重复提交防护、手动重试和迟到响应隔离。
- `src/components/FileUploadDialog.tsx`：选择文件、上传状态、元数据和下载操作。

使用 FormData 的 `file` 字段，不设置 Content-Type，不传 userId。只有 HTTP 成功、业务 code 为 SUCCESS_0000 且文件状态为 UPLOADED 时显示成功。
当前 fetch 不提供上传字节进度，仅显示等待/上传中，不模拟百分比。UPLOADED 只表示已存储。

下载使用返回的原始 downloadUrl，保留域名、路径和所有签名参数。Web 端打开下载地址，Tauri 端调用已有 opener 打开系统浏览器，依赖后端附件下载响应；不做内联预览。urlExpiresAt 支持日期字符串或 Unix 秒/毫秒时间戳；有效期无法识别时禁用下载。过期后不提供刷新接口。

网络或超时错误不代表文件没有保存。重试由用户手动触发，界面明确提醒可能生成新文件。移除仅清理本地列表，上传中的条目不能移除；无文件删除接口调用。
chat_stream 请求及 Agent 消息结构均未修改。

## 自动验收

Node.js 22.18+：`npm run test:files`。
测试使用模拟 fetch 与内存文件，涵盖：

- 正常单文件 multipart 上传、路径去重、全部返回字段保留。
- 空文件、20 MiB 边界/超限、扩展名白名单和大小写。
- 全部约定的 400/413/429/500/503 错误码，优先展示 info。
- HTTP 200 业务失败、非 JSON、缺失 info、异常成功响应。
- 网络错误、请求超时、响应体中途断开。
- 两路并发、等待后端响应才成功、防重复提交、保留失败文件、手动重试。
- 中断后的迟到响应不覆盖新上传结果。
- 下载有效期边界、异常时间、原始签名 URL 保留。

## 手动验收（需要可用后端）

1. 无 SSH 会话时打开上传，选择 txt/png/pdf；确认显示上传中、成功、名称/大小和文件信息。
2. 连续选择至少三个文件，确认网络面板同时最多两个 POST，均为 multipart 的单个 file 字段。
3. 上传中重复选择相同文件；确认没有新请求。关闭并重新打开弹窗，队列和结果应保留。
4. 选择空文件、超过 20 MiB 的文件和 exe；应显示失败原因，网络面板不出现上传请求。
5. 后端未配置存储时上传；应显示后端 info，失败文件可手动重试。
6. 上传中断网或令响应超时；不应自动重试，应显示可能重复上传的提示。
7. 成功后下载，确认地址与返回 downloadUrl 一致；浏览器休眠/切换后台后超过有效期，按钮应变为「下载链接已过期」。
8. 移除成功记录，确认只移除前端行，不发 DELETE，也不提示服务器文件已删除。
9. 在浅色/深色主题检查弹窗；上传文件不应新增聊天消息或改变 chat_stream 请求。

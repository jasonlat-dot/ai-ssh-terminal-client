# 聊天附件

输入框底部的「附件」支持多选；图片、PDF 和 UTF-8 文本文件共用同一队列。
聊天白名单不包含 DOCX/XLSX，独立文件上传入口仍允许存储这两类文件。
每条消息最多 4 个附件，原始文件总大小最多 20 MB（20,000,000 字节），不接受空文件。
加入文件、剪贴板粘贴、重新附加、上传重试及发送均使用 `src/state/chatAttachments.ts` 中的校验逻辑。
选择超限或不支持的文件时拒绝整个新增批次，不部分上传。

## 数据流程

- `FileUploadQueue` 复用原 `POST /api/v1/files`，单请求单个 FormData.file，120 秒超时，队列并发上限 2。不自动发送消息或无限重试。
- 聊天草稿队列独立于顶栏「文件上传」列表。关闭/切换聊天会话时取消旧草稿上传；切换 SSH 页签不改变聊天草稿。
- `AgentPanel` 只在 textarea 的 paste 事件处理实际 File：优先读取 items，取不到实际文件时才回退 files，不重复添加。图片无文件名时只基于真实 File 的图片 MIME 补扩展名。
- 纯文本粘贴完全保留原浏览器行为；混合粘贴阻止默认插图，文本插入当前光标/选区，文件进入同一队列。普通 URL、路径、Base64 文本不会转成文件，也不会读取本地路径。
- 正在上传、等待上传或失败的任一附件都会阻止整条消息发送。仅附件也可发送，不要求 SSH 已连接。
- `App.sendMessage` 在首次 await 前复制本次附件元数据；请求中只增加 `attachments: [{fileId}]`，保留原 agentId/userId/sessionId/message/terminalSessionId。File、Blob URL、Base64、下载地址都不会进入聊天请求。
- 发送期间保留并锁定草稿，成功后清空，失败/停止后原文字与附件保留。切换聊天后，旧请求无法清空或覆盖新草稿。

## 结果、重用及生命周期

用户消息展示文字和附件卡片。再次附加只使用已有 fileId，不读取过期下载地址，也不重新上传。恢复请求会恢复原文字与附件引用；当前已有草稿时会提示先清空，防止覆盖正在编辑的内容。
移除上传中附件会取消浏览器请求并隔离旧回调；移除已上传附件只取消引用。取消不保证后端未保存，没有调用删除接口。

图片预览使用本地 Object URL。App 根据当前草稿和消息引用统一回收，草稿清空后仍被消息使用的预览不会失效；切换会话或退出时释放无引用 URL。本地历史只保存附件元数据/fileId，不持久化 Blob URL 或 File。重新打开历史不会自动下载原图片，但仍可再次附加具有完整元数据的原 fileId。
下载按原始 downloadUrl 和 urlExpiresAt 判断，不修改签名 URL，不提供刷新接口。链接过期只禁用下载，不禁用再次附加。

## 流式错误

继续使用 POST fetch 逐行 JSON 解析，兼容原 SSE data 行，不使用 EventSource。
收到 event=error 或业务错误 envelope 时抛出带 code/content 的 ChatRequestError、取消 reader 并结束等待；错误后不处理后续 done。
只有明确 done（含兼容的 [DONE]）才确认完成，普通 EOF 视为流中断。
所有约定附件错误码都有相应的修复提示；后端 content/info 原文优先展示，包括文本正文超限。模型不支持附件时不会自动删附件重发。

## 检查

- `npm run test:chat-attachments`：剪贴板来源去重、混合粘贴、总量/类型限制、双并发、失败重试、上传中移除、会话清理、仅附件发送、引用复用、预览回收、流式 error/EOF/done、各附件错误码。
- `npm run test:files`：独立上传的原有验收回归。
- `npx tsc --noEmit`：前端类型检查。

以上为模拟文件和响应的自动检查，不会上传真实文件。
实际浏览器/客户端还需联调：截图粘贴、仅文本 Ctrl+V/Command+V、文件与文本混合粘贴、多文件选择、网络中断后手动重试、上传中移除、发送后立即切换聊天，以及历史再次附加。系统文件管理器若未提供实际 File，请用附件选择器。

# v0.2.2 升级与发布

## 从 v0.2.1 升级

1. 等待正在进行的回复、命令和文件传输结束，从系统托盘选择“退出”。仅关闭窗口会隐藏到托盘。
2. 备份 `%LOCALAPPDATA%\com.jasonlat.shellpilot\`；若设置了外部数据目录，也备份该目录。应用完全退出后再复制数据库，保留配置、附件及可能存在的 SQLite 配套文件。
3. 覆盖安装 `ShellPilot_0.2.2_x64-setup.exe`，或通过旧正式版“关于与更新”检查、下载、确认安装。无需卸载或删除数据。
4. 启动后确认版本为 0.2.2，连接、模型、历史及附件仍在。首次初始化会依次执行迁移，最终为 schema 24。
5. 旧单模型配置直接作为单模型渠道显示，原模型配置 ID 与加密密钥保持；首次编辑渠道时可增加多个模型 ID。模型移除后不再用于新请求，原聊天历史仍保留。

应用标识、安装名称、GitHub 更新地址和签名公钥不变。v0.2.1 的正式目录继续使用，不重新搬迁已初始化的数据；旧预览版迁移逻辑保留。旧 Java 数据不自动导入。

## 数据变更与回退

| 迁移 | 用途 |
| --- | --- |
| schema 22 | 保存协议原生推理和工具续接状态 |
| schema 23 | 保存模型切换边界及请求错误信息 |
| schema 24 | 保存多模型渠道、成员关系和版本信息 |

历史正文和工具证据保留。供应商原生状态不跨模型、端点或凭据转发；旧版本未保存的状态不会被编造或补回。切换到较小上下文窗口时，仍受目标模型容量限制。

不提供数据库降级。需要回退时，完全退出 v0.2.2，保留一份升级后数据，再安装旧版本并恢复升级前完整备份；升级后的新对话不在旧备份内。

## 日志排查

- 默认目录：`%LOCALAPPDATA%\com.jasonlat.shellpilot\logs\agent\YYYY-MM-DD\<traceId>.log`，内容为每行一个 JSON 对象。
- “本地工作区 → 诊断日志”设置级别及保留天数；默认 INFO / 7 天，启动、保存日志设置及运行期间每小时执行过期清理。
- 失败回复内点击“定位日志”选中该请求文件；日志未生成、已清理或不可访问时会显示错误。
- `backend.log` 主要记录工作区初始化与停止；对话历史、工具结果保存在 SQLite。清理请求日志不删除聊天或附件。
- 正文日志为本机明文，WARN / ERROR 会过滤 INFO 正文。请对拟分享的日志脱敏，不上传完整工作区或密钥。

## 本地发布

两个仓库须为匹配的 0.2.2 源码，并保持平级目录。客户端 npm、Tauri、Cargo 及两端锁文件的本项目版本均为 0.2.2。第三方依赖版本无需随应用版本更改。

在 Windows x64 客户端目录运行；沿用既有签名私钥环境变量：

```powershell
npm ci
npm run release:windows -- --notes docs/releases/v0.2.2.md
```

产物目录 `release/v0.2.2/`：

```text
ShellPilot_0.2.2_x64-setup.exe
ShellPilot_0.2.2_x64-setup.exe.sig
latest.json
SHA256SUMS
release-notes.md
```

脚本只本地构建、验签和生成文件，不创建标签或上传。把匹配的一组产物上传到客户端仓库 `v0.2.2` 正式 Release 并设为 Latest，旧客户端才可发现更新。清单和签名由实际安装包生成，不手工复用 v0.2.1 的文件。签名环境变量示例见 [README 构建和发布](../../README.md#构建和发布)。

## 安装包生成后验收

- 用实际 v0.2.1 工作区备份做覆盖升级，检查版本、历史、附件、SSH 及旧密钥可用，重启后仍保留。
- 核对旧单模型渠道、多个模型选择、同会话换模型、Claude 强度保存与工具续聊。
- 核对失败卡片、Trace ID 定位、完整输出展开与复制、选区 Ctrl+C 和返回最新回复。
- 用专用测试目录检查日志默认值和过期清理；不修改真实日志日期来制造测试数据。
- 核对签名、SHA256、`latest.json` 的版本 / 下载地址 / 安装包名称；在正式模式验证 0.2.1 → 0.2.2 的更新安装。

源码检查与回归通过不等同于签名安装包和真实在线升级已验收；上述包级检查须在生成实际产物后完成。
